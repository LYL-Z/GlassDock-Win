### 来源与结论边界

Apple 官方页面支持其明确写出的 macOS 语义和设置能力，但不能代替机器观察。Microsoft/Windows 行为、Windows Shell 映射和项目目标均作为产品/工程提案记录，不归因给 Apple。

逐条审查发现的主要来源边界：

- DOCK-003：App icon HIG 与 Materials HIG 不能证明 Dock 背板的背景模糊、光学参数或阴影。
- DOCK-005：App icon HIG 是图标设计指导；Apple 权利页面是权利核查入口，不是图标资产规范或授权。
- DOCK-013：Apple 的“点击打开应用”不证明 Windows 的前台激活、HWND 选择或非激活启动。
- DOCK-014/016/045：Dock menus HIG 是交互设计指导；不同应用菜单内容可变，不保证存在统一窗口选择器或 Windows Jump List 等价能力。
- DOCK-021：Finder 出现在 Apple 指南的使用示例中，不证明 Finder 是所有设备的默认固定项目。
- DOCK-025：来源点名 Fan、Grid、List。验收不允许用另一种视图替代后仍报 PASS。
- DOCK-027：AppKit 的空/满 Trash 资源名不能证明 Dock 的状态切换时机或视觉。
- DOCK-032：Apple 管理 payload 可配置 Genie/Scale，但这不证明动画画面、时序或外部项目的实现能力。
- DOCK-041：Apple 全屏来源仅说明 macOS app fullscreen；对 Windows 无边框或 DXGI 独占行为没有证明力。
- DOCK-042：Apple 资料说明 Light/Dark/Auto 系统外观，但没有给 Dock 自定义主题规范。
- DOCK-046：Apple 的自动隐藏设置不能证明 Windows 任务栏共存、工作区策略或恢复能力。

来源页面：[Use the Dock on Mac](https://support.apple.com/en-gb/guide/mac-help/mh35859/27/mac/27)、[Desktop & Dock settings](https://support.apple.com/en-ie/guide/mac-help/mchlp1119/27/mac/27)、[Dock folders and Stacks](https://support.apple.com/en-gb/guide/mac-help/mchl231f08fb/27/mac/27)、[Dock menus HIG](https://developer.apple.com/design/human-interface-guidelines/dock-menus)、[Materials HIG](https://developer.apple.com/design/human-interface-guidelines/materials)、[Dock management payload](https://support.apple.com/guide/deployment/dock-payload-settings-depef1fdf19/1/web/1.0)、[Light/Dark appearance](https://support.apple.com/en-gb/guide/mac-help/mchl52e1c2d2/27/mac/27)。每项的细化范围见矩阵 `EvidenceScopeReview` 与 [官方资料笔记](official-reference-notes-2026-10-23.md)。

Trash 状态/打开/投递项从 P0 调整到 P1，只表示它们不阻挡最小 app 导航与 Core 切片；它们仍保留在原阶段要求中。**只要 Recycle Bin/Trash 对应功能计划发布，DOCK-028 的清空确认与 DOCK-029 的可恢复 Shell 操作就是该功能的发布阻断验收项；任何失败都不能用永久删除回退。**

纠正后的主要依赖方向：

- 单显示器 Dock 定位不依赖 DOCK-040 多显示器；多屏为后续扩展。
- 图标身份不依赖玻璃材质；运行指示依赖 app/window 状态来源，不依赖启动/激活命令。
- 激活已有窗口不依赖运行指示点或新启动路径，采用独立前台请求结果。
- Trash 状态展示不依赖“打开/清空/投递”命令；三者共享 Shell 状态/身份层。
- “最小化进 app 图标”和“成为 Dock 独立项”是互斥表示模式，不是前后依赖。
- 单显示器自动隐藏不依赖多显示器策略；多屏拓扑变化单独验收。

依赖文字中没有缺失的 DOCK ID 引用。验收中对精确尺寸、动画参数和未经负责人选择的首次运行默认设置保留未定；这不是允许被实现者自行猜测的空白。

### 覆盖缺口与边界

将 Apple 页面中的附带行为纳入既有 ID 的验收补充，不新增需求：Stack 点桌面/同一 Stack 折叠；菜单命令随项目状态变化；拖出仅移除 Dock 引用；运行徽标使用受信任来源；窗口/显示状态改变后恢复。若后续来源复核发现新的独立功能，应走正式需求变更记录，不能静默追加到本版本。

产品决定现已记录于 [项目负责人决策记录](owner-decisions.md)。M1 规格仍保持 PROVISIONAL；Mac 实机视觉/行为取样和剩余产品边界评审完成前不得冻结。

## 2026-10-23 产品决策修订

负责人确认 D-01～D-09，允许据此更新 Windows 产品设计和启动默认值。它们不是 Apple 官方行为结论，也不代表实现已通过：

- 首启包含 Explorer 功能映射；Dock 默认位于底部；不修改 Windows 任务栏。
- 近期 App 默认开启且最多三个，只依据可靠本地观察、不上传、可关闭/清除；没有来源就显示为空。
- 保留可自定义的语义分区，移除只删 Dock 引用；清空回收站须明确确认且初始版本不可默认跳过。
- Windows 系统正确性优先于危险绕过；macOS 特殊快捷键不默认映射，后续可作为高级可配置项。
- 默认跟随 Windows 明暗主题并可独立覆盖；最终材质数值等待 Mac 实机样本。
- P0=15/P1=26/P2=5 作为可调整的排期参考，全部原始需求仍保留。

本次修订只确认 Windows 产品政策和 M2 Core 默认状态，不更改 M0 **NO-GO**、M1 **PROVISIONAL**、Mac 观察 `NOT TESTED` 或原生产窗口宿主/渲染路线未冻结状态。
