## 原始分类的初步解释

`12_功能对照矩阵_资料来源.md` 的 E/A/R/X 分类为目标规划：E 表示 Windows 有接近等价的公开能力，A 表示需近似/受 Windows 约束，R 表示需 Mac 实机采样，X 表示仅预留或不安全/无法原样实现。它不等于该条功能已证明可行。条目同时含多分类时，实施前拆分各子能力及依赖。

## 关键工程限制（研究判断，不是实测结论）

1. **Handoff / Force Quit / Finder / Genie 不存在所有语义上一一对应的 Windows 服务。** 设计必须写映射、降级或明确不实现；用户数据不可因追求相似而越权读取或静默结束。
2. **公开 Windows API 不保证强制前台切换。** 应定义“请求激活 + 提供焦点未转移提示”的失败语义，不以强制夺焦为目标。
3. **Windows Acrylic 与 Apple Liquid Glass 不是同一材质。** 现有 Dock HWND 没有通过跨窗口 blur；Windows 系统层级能力仍需经一次最小授权实验确认。
4. **应用与图标身份不能只靠进程名。** 打包应用、快捷方式、启动器、多个窗口、提升权限和辅助进程需要分开验证。
5. **回收站动作具有破坏性边界。** 删除请求必须使用系统可恢复语义并对不支持的介质拒绝执行；清空必须单独确认。

## 下一步拆分原则

M1 先把每条矩阵中的验收种子改写成 Given/When/Then 和失败路径；M0 技术 gate 通过前不写依赖该 HWND/renderer 的生产组件。随后由 M2 定状态与动作契约，M3 验证窗口/多显示器，M4/M5 逐步落地图标/材质/动效，M6–M10 建 Shell/文件/自动隐藏/无障碍，M11 做综合性能与发布。此处仅建议方向，不重写各原始 DOCK 阶段。
