# M0 范围变更记录（2026-10-23）

状态：经项目负责人提出的阶段计划变更；仅调整验收归属，不修改原始任务书、原始产品目标或历史测试结论。

## 变更原因

原始 M0 将基础工程、路线比较、玻璃外观、多个 DPI/刷新模式、全屏共存和较完整性能验收同时作为退出条件。现有 33 项矩阵因此长期无法退出。原始要求仍有效，但要在其规定的 M0/M1/M3–M11 阶段执行；M0 只保留会直接决定能否继续实施的工程和架构门槛。

本变更不把失败或未测改成通过。原始 `REQ-matrix.md` 的状态/证据作为变更前基线保留；逐项的新归属和风险见 [M0→M1 需求迁移矩阵](M0-to-M1-requirement-migration.md)。原始任务书 ZIP 未修改。

## M0 新退出责任与本轮结果

M0 必须证明项目基础可维护、两个候选可构建运行、核心状态/几何单测和远程 CI 可靠、窗口/输入基本路线存在可实施证据，并产出有证据的 ADR 和 M1 任务书。2026-10-23 最终受限试验已得到如下结果：

1. WinUI Composition 独立控制窗口显示真实 blur；项目 Dock HWND 的 XAML Border blur 候选未显示可辨 blur，当前目标窗口集成 FAIL。
2. WPF 非激活启动因脚本未在 12 秒内定位可见 HWND 而 BLOCKED；WinUI 及 DXGI companion 未执行。脚本恢复标志 false 是测试进程环境变量清理缺陷；桌面关键恢复观察仍有通过记录。

因此本次阶段结论是 **NO-GO**，M1 不开始、技术路线不冻结。不得因预算收尾把上述失败或阻断改为通过。仅在新的明确桌面授权后，才考虑一次目标 Dock HWND 的 system-backdrop 验证；若仍无真实 blur，则停止当前集成路线并重新评估替代后端，不扩场景矩阵。

## 分类

### A 类：M0 必须完成

- 工程分层、两候选可构建/可启动、核心单元测试、干净克隆基线和 GitHub Actions。
- 两候选路线比较与基本窗口/输入机制可行性证据；默认 WinUI 透明输入失败及 WPF 通过记录均保留。
- 一次受限 Composition blur 能力/宿主兼容性实验，以及一次非激活启动/必要时 DXGI 状态的窗口行为实验。
- 架构决策记录、M1 任务书、所有需求的阶段映射和风险。

### B 类：移交相应实施阶段

- 高精度 Dock、Liquid Glass 完整材质、图标资源与动态光学效果 → M1 规格冻结、M4 实现与视觉验收。
- 图标放大/弹跳/动画系统、逐帧性能优化 → M5 实现、M11 量测与验收。
- 多窗口、应用识别、托盘完整体验、辅助功能、设置和恢复 → M6/M10/M11，按需求 ID 保留。
- 自动隐藏、游戏状态、任务栏与多屏全屏恢复 → M9。
- DPI/显示器/刷新模式对照和设备兼容矩阵 → M3/M9/M11 硬件补测；当前设备不具备的组合属于 C 类依赖，不写 PASS。

### C 类：环境依赖或独立治理

- 设备不支持的显示器、DPI、刷新率和 HDR/VRR 组合：记录未测状态、硬件条件及补测阶段。
- 许可证选择：维持原 `LICENSE` 文件；建立独立公开发行门槛，等权利人选择后执行。
- 需要额外系统权限的 ETW/PresentMon 数据：维持 BLOCKED，未获授权前不提权；Dock 自身内部时间分布移交 M11。
- Apple/第三方图标和品牌素材：按 M1 素材来源与授权台账审查；项目代码许可证不覆盖第三方素材权利。

## 状态规则与不可豁免事项

沿用 `PASS / FAIL / BLOCKED / NOT TESTED`。脚本存在不等于场景测试通过，WGC 捕获成功不等于视觉通过，本地构建不等于 CI 通过。B/C 只是阶段归属调整，不是豁免；未经负责人单独批准，不得降低其原始质量标准或把它们记作 PASS。许可证不作为纯技术研究的阻断项，但仍是公开发行的阻断项。
